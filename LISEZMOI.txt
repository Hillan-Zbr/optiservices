Optiservices - banc de test des tournées AMD
=============================================
Installé sur le serveur Docker du réseau local, dans /srv/optiservices (clone git du dépôt GitHub).
  docker-compose.yml   services osrm, vroom et web (ports 5000, 3000 et 8080)
  nginx.conf           proxy vers VROOM, OSRM et le géocodage IGN
  web/                 application statique (servie telle quelle par nginx)
  osrm/                carte PACA + Corse prétraitée (hors git, régénérable : voir DEPLOIMENT-VPS.MD)
  .env                 propre au serveur, hors git. Sur le serveur du réseau local, il contient
                       COMPOSE_FILE=docker-compose.yml pour ignorer docker-compose.override.yml (réservé au VPS)

Cycle de mise à jour :
  1. développement sur le poste, directement sur main (branche unique), tests : node tests/*.test.mjs
  2. commit puis push de main sur GitHub
  3. sur le serveur :
       cd /srv/optiservices
       git pull
  4. recharger la page dans le navigateur (web/ est servi directement, pas de redémarrage)
     Seulement si docker-compose.yml, nginx.conf ou vroom-conf/ ont changé :
       docker compose up -d
       docker compose ps                    (osrm, vroom, web : running)
  Ne jamais committer sur le serveur : il ne fait que des git pull.

Accès : http://<nom-ou-IP-du-serveur>:8080

Test rapide du proxy depuis le serveur :
  curl -s "http://localhost:8080/geocode/search?q=Riez&postcode=04500&limit=1" | jq '.features[0].properties.label'
  curl -s "http://localhost:8080/osrm/route/v1/driving/5.4474,43.5297;5.3698,43.2965?overview=false" | jq '.routes[0].distance'

Données : paramètres, AMD et RDV sont stockés dans le navigateur (localStorage).
  Bouton "Exporter la configuration" pour sauvegarder / transférer paramètres et AMD.
Réseau : le serveur doit joindre data.geopf.fr (géocodage) ; le navigateur doit joindre tile.openstreetmap.org (fond de carte).

Journal d'activité (bouton « Aide » en haut à droite) :
  Trace les intégrations CSV (fichier, lignes ignorées, types de visite et AMD inconnus), les actions
  utilisateur (modifications d'AMD, de RDV, de paramètres, exports, optimisations) et les erreurs.
  Chaque ligne a un niveau : INFO (information), WARN (à vérifier), CRIT (bloquant).
  Filtres : niveau, catégorie, période, recherche texte. Export CSV (Excel) des lignes filtrées.
  Stockage : navigateur (localStorage, clé optiservices.journal.v1), 3 000 dernières lignes.
  Les RDV sont référencés par leur n° Isadom, pas par le nom du patient.
  Fichiers : web/js/journal/journal-core.js, web/js/journal/journal-view.js, web/css/journal.css
  Tests : node --test tests/journal.test.mjs
